## Запуск

Требуется Python 3.12 и Postgres 16.

```bash
cd backend && python3 -m venv venv && ./venv/bin/pip install -r requirements-dev.txt
```

База — либо через Docker (`docker compose up -d` в корне), либо локальный Postgres.
Оба варианта слушают порт **5433**, поэтому `DATABASE_URL` одинаков.

```bash
cp .env.example .env
```

Заполнить в `.env`: `TELEGRAM_BOT_TOKEN`, `TMDB_API_TOKEN`, `SECRET_KEY`, `BOOTSTRAP_SUPERADMIN_TG_ID`.

```bash
cd backend && ./venv/bin/alembic upgrade head
```

```bash
cd backend && ./venv/bin/uvicorn app.main:app --reload
```

Документация API: http://localhost:8000/docs

## Ключевые решения

**Вес нигде не материализован.** В `interests` лежат только сырые события. Формула §4
собрана как SQL-выражение в [weights.py](backend/app/services/weights.py), поэтому
изменение периода полураспада немедленно пересчитывает всю историю, а песочница §13
получается бесплатно — те же данные, другие коэффициенты в том же выражении.

**Просроченная `SOON` весит ноль, даже если крон её ещё не снял.** Формула не полагается
на пунктуальность планировщика.

**Enum'ы — `VARCHAR + CHECK`, не нативные типы Postgres.** Добавить значение в нативный
enum внутри транзакции нельзя, пересобрать CHECK — можно. Спек требует расширяемости
без ломающих миграций.

**Параметры §13 живут в реестре кода**, в БД — только переопределения
([settings.py](backend/app/services/settings.py)). Новый параметр не требует миграции
данных, а забытый ключ берёт значение по умолчанию.

**Фильм попадает в каталог в момент первой отметки**, а не при поиске — иначе база
засорялась бы всем, что кто-то когда-то набрал. Поиск отдаёт результаты TMDB с `id=null`
и `in_catalog=false`.

**Слот описан как `(зал, дата, время, длительность)`** при одном зале и фиксированных
19:00 — чтобы §19 (несколько залов, блоки по 2,5–3 часа) не ломал модель.
