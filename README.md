# Университетский киноклуб

Телеграм-бот и Mini App для клуба, который каждую неделю выбирает фильм
голосованием и показывает его в университете. Реализация по
[docs/SPEC.md](docs/SPEC.md); ссылки вида «§4» в коде и ниже — на разделы спека.

Бой: **https://cinema.cu3rd.ru**

## Словарь

Термины встречаются и в коде, и в интерфейсе:

* **Цикл (round)** — одна неделя: от сбора интереса до показов. Живёт
  в таблице `rounds`, у него есть стадия.
* **Отметка (interest)** — «Желаемое» или «Ближайшее» на фильме. Взаимоисключающие.
* **Вес** — вклад отметки в рейтинг фильма; затухает со временем. Нигде
  не хранится, считается формулой при чтении.
* **Шорт-лист** — фильмы, попавшие в голосование на неделю.
* **Слот** — `(зал, дата, время, длительность)`; вечер, в который может
  встать показ.
* **Показ (screening)** — фильм, поставленный в слот.
* **Подтверждение (confirmation)** — «приду»; при переполнении зала человек
  попадает в **лист ожидания** (FIFO).
* **Явка (attendance)** — факт прихода, отмеченный кодом или вручную.
* **Ручное событие** — показ или встреча, назначенная админом в обход цикла.
* **Лента** — режим быстрой разметки каталога свайпами.

## Быстрый старт

Подробно, с нуля и с объяснениями — в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
Коротко, если Python 3.12, Node 20+ и Postgres 16 на порту 5433 уже есть:

```bash
cd backend && python3 -m venv venv && ./venv/bin/pip install -r requirements-dev.txt && cd ..
cd miniapp && npm install && cd ..
cp .env.example .env      # заполнить TELEGRAM_BOT_TOKEN, KINOPOISK_API_TOKEN,
                          # SECRET_KEY, BOOTSTRAP_SUPERADMIN_TG_ID
cd backend && ./venv/bin/alembic upgrade head && cd ..
cd backend && ./venv/bin/python -m app.import_top --source kinopoisk --list popular --limit 1500 && cd ..
```

Дальше три процесса, каждый в своём терминале:

```bash
cd backend && ./venv/bin/uvicorn app.main:app --reload --reload-include ../.env   # API :8000
cd miniapp && npm run dev                                                          # Mini App :5173
cd backend && ./venv/bin/python -m app.bot                                         # бот
```

`--reload-include ../.env` обязателен: uvicorn следит только за `.py`, а
конфигурация читается один раз при старте — без флага правка токена не
подхватится, и приложение будет уверять, что токен не задан.

Swagger — http://localhost:8000/docs. Без запущенного бота `/start` в Telegram
останется без ответа: API и Mini App сами по себе на сообщения не отвечают.

### HTTPS-туннель

Telegram не принимает `localhost` и `http` — Mini App должен быть доступен по HTTPS.
В разработке это туннель:

```bash
scripts/tunnel.sh
```

Скрипт держит туннель, пишет адрес в `.env` и **сам переподключается**, когда
бесплатный лимит (около часа) истекает.

Править BotFather при этом не нужно: запущенный бот следит за `.env` и переставляет
кнопку меню через Telegram API (`setChatMenuButton`). От смены адреса до новой
кнопки — несколько секунд. Поэтому бот стоит держать запущенным вместе с туннелем.

Единственное, что осталось ручным: при первом открытии pinggy показывает
страницу-предупреждение, на ней надо нажать «Enter site» — дальше согласие
запоминается в cookie. Обойти её можно только своим заголовком запроса, а заголовки
Telegram мы не контролируем.

Проверены и отвергнуты: serveo (такая же заглушка), localtunnel (теряет две трети
запросов), Cloudflare Tunnel (в этой сети не соединяется — обрыв на TLS-рукопожатии).

Туннель — только для разработки. Развёртывание на сервер описано в
[deploy/README.md](deploy/README.md).

### Просмотр интерфейса локально

```bash
scripts/preview.sh            # последний коммит (не рабочая копия!)
scripts/preview.sh pr-1       # любая ветка или ревизия — например, чужой пулреквест
```

Поднимает бэкенд и Mini App на локальной базе, наполняет её демо-данными и
печатает по ссылке на каждую роль — зритель, модератор, админ, главный. В ссылке
подписанная `initData`, та же, что выдаёт Telegram, поэтому приложение впускает
как обычно и смотреть можно в любом браузере. Подпись живёт сутки; чтобы обновить,
достаточно перезапустить скрипт.

Ревизия распаковывается в `.preview/<sha>` (`git archive`), а не выкачивается
переключением ветки: чужой пулреквест смотрится, не прерывая свою работу и не
трогая рабочую копию. Демо-данные добавляет `app.preview_seed` — четыре роли,
показ через три дня с записавшимися, отметки и оценки, чтобы ни один экран не
оказался пустым. Ничего не удаляет, повторный запуск не дублирует.

### Стартовый каталог

```bash
cd backend && ./venv/bin/python -m app.import_top --source kinopoisk --limit 100
cd backend && ./venv/bin/python -m app.import_top --source kinopoisk --list popular --limit 1500
```

Первая команда завозит топ-100 из топ-250 Кинопоиска — курируемый рейтинг, а не
просто самое популярное. Вторая берёт широкий список известного кино: ленте
одного топ-250 мало, её пролистывают за пару вечеров. Обе идемпотентны:
повторный запуск обновит карточки, а не создаст дубли.

Импорт заодно подтягивает оценки TMDB по связке `externalId.tmdb` (если токен
TMDB задан и сеть до него достаёт) и прячет двойников — тот же фильм, заведённый
и из TMDB, и из Кинопоиска. Карточку, за которой стоят чьи-то отметки, он не
прячет никогда: такие пары остаются на ручное решение.

Есть и путь через TMDB, как требует §11 (список берётся из Кинопоиска, данные —
из TMDB по `externalId.tmdb`, а позиции без связки ищутся по оригинальному названию):

```bash
cd backend && ./venv/bin/python -m app.import_top --source tmdb --limit 100
```

Он требует доступа к TMDB. Из сетей, где TMDB заблокирован, не пройдёт — и, что
важнее, там же у пользователей не будут грузиться постеры, потому что
`image.tmdb.org` блокируется вместе с API. Кинопоиск отдаёт постеры со своего CDN,
доступного там же, где и сам API.

## Развёртывание

Боевая версия: **https://cinema.cu3rd.ru**

Всё крутится в Docker — на хосте не ставится ни Python, ни Node, ни Postgres.
Обратный прокси (Caddy) на сервере направляет домен на `127.0.0.1:8089`, а статику
Mini App отдаёт само приложение. Подробности и порядок обновления —
в [deploy/README.md](deploy/README.md).

```bash
deploy/sync.sh user@сервер                                  # локально
docker compose -f docker-compose.prod.yml build             # на сервере: сначала сборка,
docker compose -f docker-compose.prod.yml up -d             # потом подъём
```

## Отступления от спека

Приняты по ходу работы, осознанно.

**Отметки взаимоисключающие.** §4 говорит «кнопки независимы, веса складываются».
По решению клуба состояний стало три: ничего, «Желаемое», «Ближайшее». Нажатие
второй кнопки снимает первую.

**«Ближайшее» не сгорает, а становится «Желаемым».** §4 предполагал снятие
отметки по истечении срока и уведомление с кнопкой «Продлить». Вместо этого вес
падает с `soon_weight` до базового и дальше затухает, а продление предлагается
в интерфейсе. Сделано в самой формуле: крон не нужен, история пересчитывается
при изменении параметров, как и всё остальное в расчёте весов.

**«Просмотрено» — отдельная сущность.** §8 снимал отметки при фиксации прихода.
Теперь это отдельная таблица `watches`, не влияющая на отметки: посмотренный
фильм можно оставить в желаемом, чтобы сходить снова.

**События можно назначать вручную, в обход алгоритма.** Спек описывает только
цикл. Администратор может поставить показ или встречу на любое время, в том
числе без фильма — с подписью вроде «ждите анонса», раскрыв название позже.
Такое событие не принадлежит циклу и не участвует в его правилах.

**Шорт-лист собирают только в окне.** Спек описывает срез этапа 1 и автопилот,
но не запрещает править список в любое время. По решению клуба ручная сборка
открыта со среды 20:00 до четверга 08:00 — между теми же дедлайнами §13,
которыми цикл двигает автопилот. До среды веса ещё набираются, после четверга
список уже ушёл в голосование.

**Лента свайпов.** Спек её не описывает. Карточка на весь экран, свайп вправо —
«Желаемое», влево — «не моё», кнопка «уже смотрел» и звёзды рядом. Отказ живёт
в отдельной таблице `film_skips` и весов не несёт: отрицательного интереса
в формуле §4 нет и заводить его ради ленты не нужно — она лишь помнит, что
фильм уже показывали.

**Оценки по пятибалльной шкале, у всех и без показа.** §8 связывал оценку
с посещением: оценить можно было только тот сеанс, на котором были, и по
десятибалльной шкале. Оценивать теперь может любой участник любой фильм прямо
из каталога — пять звёзд с половинками. Оценка из формы после показа попадает
туда же: рейтинг у фильма один, откуда бы она ни пришла. Порог §11 «не
показывать рейтинг, пока оценок меньше пяти» на карточке снят — рядом всегда
стоит число оценивших, и оно честнее порога; в топе «лучшее в клубе» порог
остался.

**Ачивки.** Спек их не описывает. Устроены ступенями: у каждой цели —
просмотренные фильмы, посещённые сеансы, оценки, друзья — четыре уровня:
бронза, серебро, золото, платина. Человек держит **высшую достигнутую**:
заработал серебро — бронза той же цели заменяется, а не копится рядом. Поэтому
в профиле четыре числа с трофеями, а не список из двадцати строк. Перепрыгнув
через ступень, он получает сразу верхнюю, а не две подряд.

Правила и пороги живут реестром в коде (`services/achievements.py`), в базе —
только факт выдачи: добавить ступень значит дописать строку, без миграции.
Начисляет их фоновая задача раз в пять минут, а не каждое действие: семь
показателей на каждую отметку не стоят того — и считаются они по всем
участникам разом. Недостающие показываются с прогрессом: «осталось три»
превращает награду в цель. Полученную ачивку не отбирают, даже если отметку
сняли.

**Секретные ачивки** до получения не показываются вовсе — ни названия, ни
условия, только счётчик «осталось столько-то». В этом и смысл: найти их должно
быть сюрпризом. Одна из них требует пройти турнир, ни разу не ошибившись,
другая — долистать ленту до конца (и только если в каталоге есть что листать:
на двух десятках демо-фильмов платина обесценилась бы).

**Именные ачивки.** Админ придумывает их на месте под конкретного человека —
«спас показ», «притащил проектор». Такому правилу в реестре места нет, поэтому
текст живёт в самой записи; в профиле она считается наравне с заслуженными
автоматом и лежит во вкладке своего уровня. Снять можно только именную:
заслуженное автоматом не отбирают.

**Каждая редкость — своя вкладка.** Нажатие на трофей открывает все ступени
этого уровня: и взятые, и те, до которых далеко. Список одних наград не отвечает
на единственный интересный вопрос — что дальше.

**Трофеи нарисованы вектором**, а не картинками: четыре иконки в трёх размерах
стоили бы лишних запросов и мутных краёв на плотных экранах.

**Показ на английском — свойство сеанса.** §19 называл «дубляж/субтитры»
отложенным; понадобился его первый кусок: один и тот же фильм клуб может
показать и с дубляжом, и в оригинале, и ачивка считает приход именно
на помеченный показ.

**Сколько фильмов смотрим за неделю — параметр клуба** (`screenings_per_week`,
по умолчанию один). Задача о назначениях сама по себе заполнила бы все семь
свободных вечеров: у каждого фильма найдётся вечер, где его ждут. Автопилот
оставляет столько показов с лучшей ожидаемой явкой, сколько клуб готов
провести; руками администратор может поставить и больше.

**Турниры.** Спек их не описывает. Админ заводит голосование-сетку на любую
тему — «лучший злодей», «лучшая комедия», — и клуб проходит её плей-офф:
1/8 → 1/4 → полуфинал → финал, по этапу в сутки. Вариантов должно быть степень
двойки: сетка должна сходиться, а «технические поражения» в развлечении лишние.
Вариант — либо фильм из каталога (название и постер подтягиваются оттуда и не
устаревают), либо своя карточка: персонажа или сцену в каталоге не найти.
Промежуточный счёт пары до закрытия этапа скрыт — по тому же доводу §11, по
которому каталог не сортируется по популярности. Ничья решается посевом: монетка
честнее, но необъяснима, а посев виден в сетке заранее. Турнир идёт один за раз.

**Друзья, профили и лента.** Спек их не описывает. У каждого участника есть
профиль: аватар и ник из Telegram, четыре любимых фильма, счётчики и недавние
действия. «Добавить в друзья» работает сразу, без подтверждения: это подписка,
а дружба — две встречные подписки. Заявок, которые надо принимать, нет вовсе.
Лента собирается из уже существующих событий — отметок, просмотров и оценок,
— ничего нового ради неё не хранится.

**Закрытая бета по кодам.** Спек этого не описывает. Пока параметр
`beta_invite_required` включён, новый участник должен ввести код-приглашение —
их выдают администраторы, у каждого кода своё число активаций. Проверка стоит
в единственной точке входа (`current_user`), поэтому закрыты и приложение, и
бот сразу. Выключает бету только главный админ; при выключении все, кто застрял
на коде, получают доступ и сообщение об этом. Пришедшие до беты не трогаются:
миграция проставила им доступ.

**Знакомство при первом запуске бота.** Спек описывает только `/start`.
Новичку показывается шесть шагов о том, что умеет клуб; перечитать — `/tour`.

**Пригласительные ссылки на фильм.** Спек их не описывает. Человек зовёт друзей
на конкретный фильм: ссылка ведёт в бота, тот показывает карточку и кнопку.
Голос **не** ставится автоматически — приглашённый решает сам, одним нажатием.
Иначе накрутить вес фильма было бы вопросом рассылки ссылки в чат, и шорт-лист
отражал бы активность одного человека, а не интерес клуба.

**Каталог сортируется по топу Кинопоиска по умолчанию.** §11 просит не
сортировать по популярности: это усиливает эффект присоединения к большинству.
Сортировка по числу голосов (она была первой версией) действительно этим
страдала, поэтому её заменили на курируемый список: он тоже ставит известное
вперёд, но не зависит от того, кто что отметил. Рядом, в один тап, — оценки
TMDB, оценки клуба, «хотят в клубе» и год.

**Веб-вход и SSO вуза отложены.** §12 описывает два способа входа. Запускаемся
только с Telegram Mini App.

**Каталог наполняется из Кинопоиска, а не из TMDB.** §11 называет основой TMDB.
Из сети, где велась разработка, он недоступен целиком — вместе с CDN постеров.
Путь через TMDB сохранён (`--source tmdb`) и на сервере работает.

## Ключевые решения

**Вес нигде не материализован.** В `interests` лежат только сырые события. Формула §4
собрана как SQL-выражение в [weights.py](backend/app/services/weights.py), поэтому
изменение периода полураспада немедленно пересчитывает всю историю, а песочница §13
получается бесплатно — те же данные, другие коэффициенты в том же выражении.

**Истечение «Ближайшего» — тоже свойство формулы, а не крона.** Отметка не сгорает:
по истечении срока она сама начинает считаться «Желаемым» и затухать от момента
истечения. Планировщик для этого не нужен, а изменение `soon_ttl_days` немедленно
пересчитывает всю историю.

**Enum'ы — `VARCHAR + CHECK`, не нативные типы Postgres.** Добавить значение в нативный
enum внутри транзакции нельзя, пересобрать CHECK — можно. Спек требует расширяемости
без ломающих миграций.

**Параметры §13 живут в реестре кода**, в БД — только переопределения
([settings.py](backend/app/services/settings.py)). Новый параметр не требует миграции
данных, а забытый ключ берёт значение по умолчанию.

**Фильм попадает в каталог в момент первой отметки**, а не при поиске — иначе база
засорялась бы всем, что кто-то когда-то набрал. Поиск отдаёт результаты TMDB с `id=null`
и `in_catalog=false`.

**Слот описан как `(зал, дата, время, длительность)`** при одном зале и фиксированных
19:00 — чтобы §19 (несколько залов, блоки по 2,5–3 часа) не ломал модель.
