## Запуск

Требуется Python 3.12 и Postgres 16.

**Все команды ниже выполняются из корня репозитория** — из папки `cinema-club/`,
той самой, где лежит этот файл. Проверить, что вы в ней: `pwd` должен оканчиваться
на `/cinema-club`.

Зависимости:

```bash
cd backend && python3 -m venv venv && ./venv/bin/pip install -r requirements-dev.txt && cd ..
```

База — либо через Docker (`docker compose up -d`), либо локальный Postgres.
Оба варианта слушают порт **5433**, поэтому `DATABASE_URL` одинаков. На машине, где
это писалось, поднят второй вариант: `brew services start postgresql@16`.

Конфигурация:

```bash
cp .env.example .env
```

Заполнить в `.env`: `TELEGRAM_BOT_TOKEN`, `TMDB_API_TOKEN`, `SECRET_KEY`, `BOOTSTRAP_SUPERADMIN_TG_ID`.

Миграции (если база уже развёрнута, ответит «already at head» — так и должно быть):

```bash
cd backend && ./venv/bin/alembic upgrade head && cd ..
```

Сервер API:

```bash
cd backend && ./venv/bin/uvicorn app.main:app --reload --reload-include ../.env
```

`--reload-include ../.env` обязателен: по умолчанию uvicorn следит только за
`.py`-файлами, а конфигурация читается один раз при старте. Без этого флага правка
токена в `.env` не подхватится, и приложение будет уверять, что токен не задан.

Mini App (в отдельной вкладке терминала, из корня репозитория):

```bash
cd miniapp && npm install && npm run dev
```

Dev-сервер Vite проксирует `/api` на бэкенд, поэтому наружу торчит один порт — 5173.

### HTTPS-туннель

Telegram не принимает `localhost` и `http` — Mini App должен быть доступен по HTTPS.
В разработке это туннель:

```bash
scripts/tunnel.sh
```

Скрипт держит туннель, пишет адрес в `.env` и **сам переподключается**, когда
бесплатный лимит (около часа) истекает.

Править BotFather при этом не нужно: запущенный бот следит за `.env` и переставляет
кнопку меню через Telegram API (`setChatMenuButton`). От смены адреса до новой
кнопки — несколько секунд. Поэтому бот стоит держать запущенным вместе с туннелем.

Единственное, что осталось ручным: при первом открытии pinggy показывает
страницу-предупреждение, на ней надо нажать «Enter site» — дальше согласие
запоминается в cookie. Обойти её можно только своим заголовком запроса, а заголовки
Telegram мы не контролируем.

Проверены и отвергнуты: serveo (такая же заглушка), localtunnel (теряет две трети
запросов), Cloudflare Tunnel (в этой сети не соединяется — обрыв на TLS-рукопожатии).

Туннель — только для разработки. Развёртывание на сервер описано в
[deploy/README.md](deploy/README.md).

### Стартовый каталог

```bash
cd backend && ./venv/bin/python -m app.import_top --source kinopoisk --limit 100
```

Завозит топ-100 из топ-250 Кинопоиска — курируемый рейтинг, а не просто самое
популярное. Идемпотентно: повторный запуск обновит карточки, а не создаст дубли.

Есть и путь через TMDB, как требует §11 (список берётся из Кинопоиска, данные —
из TMDB по `externalId.tmdb`, а позиции без связки ищутся по оригинальному названию):

```bash
cd backend && ./venv/bin/python -m app.import_top --source tmdb --limit 100
```

Он требует доступа к TMDB. Из сетей, где TMDB заблокирован, не пройдёт — и, что
важнее, там же у пользователей не будут грузиться постеры, потому что
`image.tmdb.org` блокируется вместе с API. Кинопоиск отдаёт постеры со своего CDN,
доступного там же, где и сам API.

### Бот

```bash
cd backend && ./venv/bin/python -m app.bot
```

Бот отдаёт кнопку, открывающую Mini App. Без запущенного бота `/start` в Telegram
останется без ответа — API и Mini App сами по себе на сообщения не отвечают.

Документация API: http://localhost:8000/docs

## Отступления от спека

Приняты по ходу работы, осознанно.

**Отметки взаимоисключающие.** §4 говорит «кнопки независимы, веса складываются».
По решению клуба состояний стало три: ничего, «Желаемое», «Ближайшее». Нажатие
второй кнопки снимает первую.

**«Ближайшее» не сгорает, а становится «Желаемым».** §4 предполагал снятие
отметки по истечении срока и уведомление с кнопкой «Продлить». Вместо этого вес
падает с `soon_weight` до базового и дальше затухает, а продление предлагается
в интерфейсе. Сделано в самой формуле: крон не нужен, история пересчитывается
при изменении параметров, как и всё остальное в расчёте весов.

**«Просмотрено» — отдельная сущность.** §8 снимал отметки при фиксации прихода.
Теперь это отдельная таблица `watches`, не влияющая на отметки: посмотренный
фильм можно оставить в желаемом, чтобы сходить снова.

**События можно назначать вручную, в обход алгоритма.** Спек описывает только
цикл. Администратор может поставить показ или встречу на любое время, в том
числе без фильма — с подписью вроде «ждите анонса», раскрыв название позже.
Такое событие не принадлежит циклу и не участвует в его правилах.

**Каталог сортируется по популярности по умолчанию.** §11 просит обратного:
такая сортировка усиливает эффект присоединения к большинству и прячет хвост
каталога. Изменено по решению клуба; остальные порядки доступны в один тап.

**Веб-вход и SSO вуза отложены.** §12 описывает два способа входа. Запускаемся
только с Telegram Mini App.

**Каталог наполняется из Кинопоиска, а не из TMDB.** §11 называет основой TMDB.
Из сети, где велась разработка, он недоступен целиком — вместе с CDN постеров.
Путь через TMDB сохранён (`--source tmdb`) и на сервере работает.

## Ключевые решения

**Вес нигде не материализован.** В `interests` лежат только сырые события. Формула §4
собрана как SQL-выражение в [weights.py](backend/app/services/weights.py), поэтому
изменение периода полураспада немедленно пересчитывает всю историю, а песочница §13
получается бесплатно — те же данные, другие коэффициенты в том же выражении.

**Истечение «Ближайшего» — тоже свойство формулы, а не крона.** Отметка не сгорает:
по истечении срока она сама начинает считаться «Желаемым» и затухать от момента
истечения. Планировщик для этого не нужен, а изменение `soon_ttl_days` немедленно
пересчитывает всю историю.

**Enum'ы — `VARCHAR + CHECK`, не нативные типы Postgres.** Добавить значение в нативный
enum внутри транзакции нельзя, пересобрать CHECK — можно. Спек требует расширяемости
без ломающих миграций.

**Параметры §13 живут в реестре кода**, в БД — только переопределения
([settings.py](backend/app/services/settings.py)). Новый параметр не требует миграции
данных, а забытый ключ берёт значение по умолчанию.

**Фильм попадает в каталог в момент первой отметки**, а не при поиске — иначе база
засорялась бы всем, что кто-то когда-то набрал. Поиск отдаёт результаты TMDB с `id=null`
и `in_catalog=false`.

**Слот описан как `(зал, дата, время, длительность)`** при одном зале и фиксированных
19:00 — чтобы §19 (несколько залов, блоки по 2,5–3 часа) не ломал модель.
